# Worklog Canvas

タスク一覧と、1日の作業時間を記録する作業バーを管理し、タスク別の作業時間と進捗を可視化するWindows用デスクトップアプリ。
記録から週報（Excel）を出力し、チームのメンバーの記録を閲覧できる。仕様は [SPEC.md](SPEC.md) を参照。

- 動作環境: Windows 11。インターネット接続は不要（通信は一切行わない）
- データは共有フォルダに保存する。利用者はWindowsのユーザー名で識別する

## 起動方法（利用者向け）

1. 配布された `WorklogCanvas` フォルダを、自分のPCの任意の場所（例: `C:\Tools\WorklogCanvas`）にコピーする。Pythonのインストールは不要。
2. フォルダ内の `WorklogCanvas.exe` をダブルクリックする。
3. 初回だけ、データを保存するフォルダ（チームの共有フォルダ）を選ぶ。選んだ場所は `%APPDATA%\WorklogCanvas\settings.json` に保存され、次回からは聞かれない。あとから「設定…」で変更できる。
4. 「設定…」で表示名（例: 福井）を設定する。チーム一覧や週報にはこの名前が出る。

## exe の作り方（開発者向け）

Windows で、Python 3.12 を入れた状態で、このフォルダの `build.bat` を実行する。

```bat
build.bat
```

1. ビルド用の仮想環境 `.venv-build` を作り、`requirements.txt` のライブラリを入れる。
2. 自動テストを実行する（省略するときは `build.bat /notest`）。
3. PyInstaller で `dist\WorklogCanvas\WorklogCanvas.exe` を作る（1フォルダ形式。`dist\WorklogCanvas` フォルダごと配布する）。
4. できた exe を `--self-test` で起動し、同梱した部品（画面、Excel出力、予定表ファイル、タイムゾーン）が動くことを確かめる。

exe を作る手順の本体は `packaging/build_exe.py`（`build.bat` と GitHub Actions の両方から使う）。

## リリースの作り方（GitHub Releases に自動で添付）

`v1.2.0` のような形のタグをプッシュすると、GitHub Actions（`.github/workflows/release.yml`）が Windows 上で次を行う。

1. 自動テスト
2. 版番号（タグの `v` を除いた `1.2.0`）を入れて exe を作り、`--self-test` で動作を確かめる
3. `WorklogCanvas-v1.2.0-windows.zip` を添付した Release を作る（リリースノートは前回のタグからの変更を自動で作る）

```bash
git tag v1.2.0
git push origin v1.2.0
```

- タグは `v数字.数字.数字` の形にする。テストか動作確認に失敗した場合は Release を作らない。
- 利用者は Release の zip を展開し、`WorklogCanvas` フォルダごと置き換える（データは共有フォルダと `%APPDATA%` にあるので消えない）。
- 版番号は「設定…」画面と `app.log` の起動の行で確認できる。
- プルリクエストと手動実行（Actions の「Release」→「Run workflow」）でも同じ手順でビルドを確かめる。この場合は Release を作らず、zip を成果物として7日間残す。

```

```

## 使い方

### タイムラインの操作

| 操作 | 動作 |
|---|---|
| 空き時間を縦にドラッグ | 作業バーを作成し、入力ポップアップを表示 |
| ポップアップで文字を入力してEnter | 単発作業として記録 |
| ポップアップで↑↓で候補を選んでEnter、または候補をクリック | タスクとして記録 |
| ポップアップでEsc | 作成を取り消す |
| 作業バーの上端・下端をドラッグ | 開始・終了時刻を変更（15分刻み） |
| 作業バーの中央をドラッグ | 移動（週表示では別の日へも移動可） |
| 作業バーをダブルクリック | 編集ダイアログ（サブタスクの追加・削除、進捗率） |
| 作業バーを選んでDelete、または右クリック→削除 | 削除 |
| 左のタスクを空き時間へドラッグ | 1時間の作業バーを作成（後ろのバーまで1時間ない場合はその手前まで） |
| 左のタスクを作業バーの上へドラッグ | そのバーのサブタスクに追加 |
| Ctrl+Z | 直前の作業バーの操作を取り消す（20操作まで） |

### 進捗率と集計

- 進捗率は、タスク一覧の「進捗率」列のスライダー（5%刻み）、タスクの編集ダイアログ、作業バーの編集ダイアログで変更できる。変更した日の進捗履歴に記録し、100%にするとステータスを完了にするか確認する。
- 「集計・週報」タブの「集計」で、日／週／期間指定の集計を表示する。
  - 日別のタスク別時間（積み上げ棒。高さ＝稼働時間）
  - 週（期間）のタスク別時間（横棒。メイン時間の降順。サブ時間は括弧内に参考表示）
  - カテゴリ別の合計時間と割合（メイン時間。割合の合計は100%）
  - タスクごとの進捗（進捗率、実績時間／予定工数、サブ時間、完了予定日までの残り日数）

### 週報

「集計・週報」タブの「週報」で、対象週（月〜日）の週報をプレビューし、Excelに保存する。

- 左の「所感・課題」「来週の予定」（各400文字以内）は入力すると自動で保存される（`weekly_notes.json`）。
- 「来週の予定」が空のときは、未完了タスクを完了予定日の近い順に5件入れる。
- 「Excel保存」で `週報_<表示名>_<週開始日YYYYMMDD>.xlsx` を保存する。A4縦1ページ（タスク実績表が20行を超えると2ページ目に続く）。
- 「テキストをコピー」で、タスク実績・単発作業・来週の予定・所感・課題をプレーンテキストでクリップボードへコピーする。
- 対象週に記録がないときは「対象週の記録がありません」と表示し、出力しない。

### タスクのCSV取り込み

「タスク一覧」の「CSVから取り込む…」で、次の形式のCSVからタスクを一括で追加する。
文字コードは UTF-8（BOM付き）または Shift_JIS（自動判定）。タスク名以外は空でよい。
`categories.json` にないカテゴリは自動で追加する。不正な行はスキップし、取り込み後に行番号を表示する。

```
タスク名,カテゴリ,完了予定日,期限
次世代基板：抵抗変更等によるマイコンのバッテリ読み取り精度の検証・評価,次世代基板,,
IC微小電流測定用の治具作成（INA226＋Arduinoのプログラム）,治具,2026-11-20,
チャージャIC：10時間充電停止の確認,チャージャIC,,
```

### 予定表ファイル（.ics）の取り込み

Outlookの予定を、タイムライン上に斜線模様の半透明のバー（予定バー）として表示する。Worklog Canvas はOutlookと直接はつながらず、通信もしない。

1. Outlook（クラシック版）で予定表を開き、「ファイル」→「予定表の保存」（Save Calendar）で .ics ファイルを保存する。
   「詳細オプション」（More Options）で、期間（例: 今後1か月）と「空き時間情報のみ」ではなく件名を含む詳細を選ぶ。
   ※ 新しい Outlook で .ics を保存できるかは実環境で確認中（SPEC.md の Q-01）。
2. タイムラインの「予定を取り込む」でそのファイルを選ぶか、ファイルをタイムラインへドラッグ＆ドロップする。
3. 予定バーを右クリック →「作業バーにする」で、同じ時間帯の単発作業（タイトル=件名、取込元=Outlook）を作る。15分刻みでない時刻は近い15分に丸める。
   既存の作業バーと重なる場合は作れない。作った作業バーはダブルクリックでタスクに変更できる。

- 繰り返しの予定（RRULE、EXDATE、一部の回だけの変更）は表示中の週の分に展開する。日時はPCのタイムゾーン（日本時間）で表示する。
- 終日の予定は、日付の見出しの下に件名だけ表示する。
- 予定バーは保存しない（作業バーにしたものだけ保存）。予定表ファイルは共有フォルダにコピーしない。最後に読み込んだファイルの場所だけを `settings.json` に覚え、週を切り替えたときはその内容から表示する。「再読み込み」で同じファイルを読み直す。
- 作業バーの下に隠れた予定は、列の左端の斜線の目印で分かる。他のメンバーの閲覧中は予定バーを表示しない。
- サンプル: `sample_data/sample_calendar.ics`（通常・終日・毎週の繰り返し・UTC表記の予定を含む）。

### 他のメンバーの閲覧・チーム一覧

- 画面上部の「表示する人」でメンバーを選ぶと、その人のタイムライン・タスク一覧・集計・週報を読み取り専用で表示する（「閲覧モード：<表示名>」と表示）。
- 「チーム」タブで、選んだ1日について全員のタイムラインを1人1列で並べ、その下に各自の進行中タスクを表示する。
- 他のメンバーの記録は自動では更新しない。「更新」ボタンで読み込み直す。読み込めないメンバーは「読み込めませんでした」と表示する。

### 設定

「設定…」で、表示名、データフォルダ（次回起動から有効）、タイムラインの表示時間帯、カテゴリ（追加・名前の変更・削除）を変更できる。
カテゴリの名前の変更・削除は、そのカテゴリを使うタスクが自分のデータに0件のときだけできる。

### 保存・バックアップ・異常時の動作

| 状況 | 動作 |
|---|---|
| 起動時に共有フォルダへ接続できない | 「再試行」「別のフォルダを選ぶ」「終了」を選ぶ |
| 使用中に保存できない | 画面左下に赤で「未保存」。30秒ごとに再試行。終了時に未保存があれば警告 |
| JSONが壊れていて読めない | `<名前>.broken_<日時>` に改名し、最新のバックアップから復元するか確認 |
| 同じユーザーが別のPCで使用中 | 警告を出して閲覧モードで起動（もう一方が終了または2分以上応答がなければ通常どおり起動） |

- バックアップ: 起動時、その日最初の1回だけ `users/<ユーザー名>/backup/<YYYYMMDD>/` にJSON（自分のファイルと categories.json）をコピーする。直近14日分を残す。
- ログ: `%APPDATA%\WorklogCanvas\app.log`（起動・終了・エラー）。1MBで世代交代し、3世代を残す。予定の件名は記録しない。

## 性能の確認（仕様8章、AC-22）

タスク500件・作業バー5000件（×10名）と予定2000件の予定表ファイルを作り、画面を実際に動かして時間を測る。

```bat
python scripts\make_perf_data.py %TEMP%\wc_perf
python scripts\measure_perf.py %TEMP%\wc_perf
```

基準（起動から操作可能まで5秒、週の切り替え1秒、チーム一覧10名分5秒、予定2000件の読み込み3秒）を超えた項目は「NG」と表示する。
exe での体感の確認は、作ったデータフォルダを指定して起動する（`WorklogCanvas.exe --data %TEMP%\wc_perf --user user01`）。

## データフォルダの構成

```
<データフォルダ>/
├─ categories.json          全員共通のカテゴリ
└─ users/
   └─ <Windowsのユーザー名>/
      ├─ profile.json        表示名
      ├─ tasks.json          タスク
      ├─ worklogs.json       作業バー
      ├─ weekly_notes.json   週次メモ
      ├─ .lock               起動中の印（二重起動の検出用）
      └─ backup/YYYYMMDD/    毎日のバックアップ（14日分）
```

JSONは UTF-8（BOMなし）・LF。各ファイルの項目名は SPEC.md 5.2 の項目名をそのまま使い、
`{"version": 1, "next_id": 4, "tasks": [...]}` のように形式の版と次の採番を持つ。

作業バーはメイン（タスクまたは単発作業）1つと、サブタスク（タスクまたは単発作業）を3つまで持てる。
作業バー同士は重ねられず、並行作業はサブタスクで記録する。

```json
{"id": "W-000001", "日付": "2026-11-10", "開始時刻": "10:00", "終了時刻": "11:30",
 "種別": "タスク", "タスクid": "T-0001", "タイトル": "",
 "サブタスク": [{"種別": "タスク", "タスクid": "T-0002", "タイトル": ""},
                {"種別": "単発作業", "タスクid": null, "タイトル": "打合せ"}],
 "メモ": "", "取込元": "手動"}
```

集計では、メインの時間（タスク別時間・稼働時間・カテゴリ別）と、サブタスクの時間（サブ時間）を分けて数える。

## サンプルデータ

`sample_data/` は次のコマンドで作り直せる。

```bat
python scripts\make_sample_data.py
```

3名（福井・佐藤・鈴木）、各自タスク8件、2026-11-02〜11-13 の作業バー（サブタスクと単発作業を含む）。
予定表ファイルのサンプル `sample_data/sample_calendar.ics` も含む（手で作成したもの。生成スクリプトの対象外）。
